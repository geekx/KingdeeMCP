# 常见报错与对策

## 被前置规则拦下(还没发请求)

返回体里 `blocked_by: "precondition"`。**这是好事** —— 问题在打到 ERP 之前就被挡住了。

| 报错 | 原因 | 怎么办 |
|---|---|---|
| 动词 X 不适用于 Y | 对基础资料用了审核类动词,或对查询视图用了写动词 | 按提示里列出的 `可用动词` 改 |
| 未登记的下推关系 A→B | 注册表里没有这条转换关系 | 提示里会列出 A 已登记的目标单。若确认本账套真有 A→B,让业务同事补进 `profiles/<租户>/profile.yml` 的 `links` 段 |
| X 要求对象处于 [...] 之一 | 当前状态不满足 | 先执行提示里给的前置动词 |
| 未知名词 / 未定义的业务操作 | 拼错或本租户没定义 | 用 `kd_describe` 查清单 |

## 打到 ERP 之后失败

| 报错 | 原因 | 怎么办 |
|---|---|---|
| 字段不存在 | 二开改了字段名 | `kd_describe(what="nouns", key=...)` 看默认字段集;仍不对说明租户配置该更新 |
| 不能为空 | 必填项没给 | 报错的 `field` 指明是哪个 |
| 关联数量 | 源单已被下推到上限 | 查源单的关联数量;可能已有下游单据 |
| 已被其他用户修改 | 并发冲突 | 重新读取后再改,不要盲目重试 |
| 已审核 | 状态不对 | 先 `unaudit` |

## 结果不可判定(`outcome: "unknown"`)

**这不是失败。** 请求已经发出但响应没收到(超时/连接中断),服务端**可能已经生效**。

1. 先 `kd_query` 查证对象是否已存在/状态是否已变;
2. 确认没生效再重试;
3. 直接重试会重复建单——`save` / `push` 没有幂等键,重复了只能人工删。

同理,`SessionAmbiguousError`(会话失效但 HTTP 200)也属于这一类,系统**故意不自动重试**。

## 操作卡在半路

```
kd_audit(scope="dangling")
```

`left_objects` 是已经产生、但整条链没走完的单据。系统不会自动回滚,
需要人决定:继续走完(补 submit/audit),还是清理掉(unaudit → delete)。

要看某一次操作的完整步骤:`kd_audit(scope="trace", trace_id="...")`。
