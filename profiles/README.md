# 租户配置填写指南（面向业务人员）

## 这是干什么的

每家公司的金蝶云星空都做过二开:表单标识不同、操作编码不同、下推关系不同、字段名不同。
与其为每家改一次代码,不如让每家在一份文件里描述自己的差异——
**同一套代码服务所有账套,差异全在配置里。**

一句话:通用能力(动词、状态、原子性契约)由底座提供,你们家的具体情况写在这里。

## 三步开始

1. 复制 `profiles/example-tenant/` 改成你们公司的名字,比如 `profiles/acme/`;
2. 打开 `profile.yml`,**只填与标准不一样的地方**——没差异的一个字都不用写;
3. 校验并启用:

```bash
python3 -m kingdee_ontology.base.validate_profile acme      # 检查填得对不对，中文报错
export KINGDEE_TENANT=acme                 # 启用
```

## 四段内容,按需要填

| 段 | 什么时候要填 | 谁最清楚 |
|---|---|---|
| `nouns` | 我们家有底座里没有的单据(二开单),或某个单据想默认多带几个字段 | 业务负责人 |
| `verbs` | 我们家的"整单关闭""作废"编码和标准不一样 | 实施顾问 / 二开同事 |
| `links` | 我们家有特有的下推关系(A 单能推出 B 单) | 业务负责人 |
| `operations` | **想把一串操作起个我们自己的名字** | 业务负责人 |

前三段是"告诉系统我们家长什么样",第四段是"告诉系统我们家怎么干活"。

## 重点:业务操作入口(`operations`)

这是给你们自己用的。用你们平时的说法给一件事命名,说明它由哪几步组成:

```yaml
operations:
  销售开票:
    owner: 财务部
    desc: 已审核的销售订单 → 生成开票申请 → 提交审核 → 生成应收单。
    confirm: true                  # 涉及金额，执行前必须让人确认
    steps:
      - {做: 确认, 问: "将对这些销售订单生成开票申请并过账应收，确认继续？"}
      - {做: 下推, 从: SAL_SaleOrder, 到: PAEZ_CustomInvoice}
      - {做: submit, 对象: PAEZ_CustomInvoice, 用: 上一步产物}
      - {做: audit,  对象: PAEZ_CustomInvoice, 用: 上一步产物}
```

定义好之后,直接说「帮我做**销售开票**,订单 XSDD001、XSDD002」就能用,
不必记 form_id,也不必记动词顺序。

`steps` 只有三种写法:

| 写法 | 含义 |
|---|---|
| `{做: 下推, 从: A单, 到: B单}` | 由 A 单生成 B 单 |
| `{做: <动词>, 对象: <单据>, 用: 上一步产物}` | 对上一步生成的单执行动词 |
| `{做: 确认, 问: "..."}` | **停下来等人点头**,不点不继续 |

动词就那几个:`submit` 提交 / `audit` 审核 / `unaudit` 反审核 /
`delete` 删除 / `close` 整单关闭 / `void` 作废 / `cancel` 撤销 / `save` 新建修改。

## 三条要知道的规矩

**① 覆盖层只能加,不能删。**
你可以新增单据、改写某个字段,但不能把底座里的条目删掉——
删掉会让通用流程在你们家静默失效,比报错更难查。

**② 只写差异。**
`SAL_SaleOrder` 你只想改默认字段,那就只写 `default_fields` 一行,
其余(允许的动词、状态、原子性)自动继承底座。

**③ 涉及金额、不可逆的操作请写 `confirm: true`。**
系统会在执行前停下来问人。删除、作废、整单关闭这类没有逆操作的动作,
即使你不写,系统也会自己拦一道。

## 常见问题

**Q:我不知道我们家某个单据的 form_id 怎么办?**
让实施顾问在金蝶里看,或者跑 `python3 -m kingdee_ontology.base.probe --search 开票` 从账套元数据里搜。

**Q:填错了会怎样?**
`validate_profile` 会用中文告诉你哪一行错了、应该怎么改。
校验不过就不会被加载,不会影响线上。

**Q:下推关系填错会有什么后果?**
不会有后果——系统在发请求**之前**就会拦下未登记的下推关系并告诉你。
真正危险的是绕过校验硬发,那会在账套里留下无人认领的中间单据。
