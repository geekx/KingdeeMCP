# 抽象层：面向 Ontology 的五元建模

把 KingdeeMCP 从"97 个函数"抽象成一个可推理的领域模型，只需要五类概念。
本文定义它们的**元模型**（是什么、必须满足什么、如何判定）；
实例见 [`02-ontology-instances.md`](02-ontology-instances.md)，机器可读版本见 [`model/`](model/)。

## 五元一览

| 概念 | 一句话 | 身份 | 载体 |
|---|---|---|---|
| **名词 Noun** | 有身份、可被操作、状态可持久化的业务对象类型 | `form_id` | `FORM_CATALOG`（48） |
| **动词 Verb** | 施加于名词、可能改变其状态的操作 | 工具名 + 端点 | MCP tools（97 → 20 类） |
| **状态 State** | 对象生命周期中一个可观测、互斥、可持久化的构型 | 规范码 | `FDocumentStatus` 等字段 |
| **链接 Link** | 两个名词实例间被持久化的、有方向的业务关系 | `(from, to, kind)` | `_LK` 关联表 + 关联数量 |
| **规则 Rule** | 对上述四者组合的可判定约束 | 规则 ID | 服务端 / harness / 无 |

## 1. 名词（Noun）

**判定标准**——三条同时满足才是名词，否则是字段、投影或参数：

1. **有独立身份**：能被 `FID` 或 `FBillNo` 唯一指称；
2. **可被动词作用**：至少有一个写动词以它为宾语；
3. **状态可持久化**：它的状态能从服务端读回，而不只是推断。

按这条标准，`STK_Inventory`（即时库存）和 `SAL_AvailableQuery`（可用量查询）
虽然登记在 `FORM_CATALOG` 里，本体上是**投影**不是名词——它们没有自己的生命周期。
当前类型系统没有把这条区分表达出来（见 `nouns.yml:gaps`）。

**身份的双轨问题**：`FID`（内码，稳定）与 `FBillNo`（业务编号，可读）并存，
而不同动词要求不同的那一个——`submit/audit/delete` 要 FID，`push` 要 FBillNo。
系统没有提供二者之间的解析动词，转换责任落在调用方。

## 2. 动词（Verb）

一个动词**必须**声明四项契约，缺一不可：

| 契约 | 取值 | 为什么必须显式 |
|---|---|---|
| `arity` | `single` / `batch` | 决定失败时的影响面 |
| `atomicity` | `atomic` / `per_item` / `server_defined` | 决定失败后调用方要不要、能不能补偿 |
| `idempotent` | `true` / `false` | 决定能不能重试 |
| `reversible` | 逆动词名 / `null` | `null` 即 destructive，决定要不要人工确认 |

MCP 协议原生只提供 `readOnlyHint` / `destructiveHint` / `idempotentHint` / `openWorldHint`，
**缺 `arity` 和 `atomicity`**——这正是本次审计 A-2 的根因：
`kingdee_audit_bills`（逐条、部分成功）和 `kingdee_void_bills`（一次提交、原子性未知）
在 MCP 的类型系统里长得一模一样。

**复合动词不是动词**。一次调用内顺序执行多个写动词的东西（`create_and_audit` 等），
本体上是"未声明事务边界的动词序列"。要把它当动词用，必须补上第五项契约：

| 契约 | 取值 |
|---|---|
| `compensation` | 每一步的逆动作，或显式声明 `none`（并承担后果） |

## 3. 状态（State）

**判定标准**——三条同时满足：

1. **可从服务端读回**，不能只存在于内存或推断中；
2. **互斥**，任一时刻对象恰处于一个状态；
3. **只能由动词改变**，查询不改变状态。

由此推出两条设计约束，当前代码都违反了：

- **状态词表必须唯一**。同一个状态不能既叫"待审核"又叫 `B`（S-1）；
  同一个码不能同时属于两个互斥语义类（S-2，`D` 既是 pending 又是 rejected）。
- **写动词返回 success 不等于状态已迁移**。`success` 只说明请求被接受；
  真实状态需要回读确认。当前 `_result_status` 直接按 `DOC_LIFECYCLE` 断言 `to` 状态，
  从不回读（`rules.yml:MISS-04`）。

**正交状态**：单据状态（`FDocumentStatus`）、关闭状态（`FCloseStatus`）、
作废状态（`FCancelStatus`）是三个正交维度，可以叠加。
把它们压成一维（当前 `DOC_LIFECYCLE` 的做法）必然丢信息——
这就是为什么"已作废"和"已审核"会返回同样的 `next_action=null`（S-3）。

## 4. 链接（Link）

**链接 ≠ 引用**。区别在于：链接承载**不变量**，改变一端会约束另一端。

- 单据引用一个供应商：这是引用（`master_reference`），只在保存时校验一次。
- 采购订单下推入库单：这是链接（`push_down`），它建立了
  `sum(下游关联数量) <= 源单数量` 的持续不变量，
  并且改变了源单能否再次被下推。

链接必须可枚举。不可枚举的链接等于没有链接——
无法校验一条下推是否合法，只能发请求让服务端拒绝（L-1）。

**链接的方向性与可逆性**：`push_down` 单向且**无逆动词**。
没有 `unpush`，解除关系的唯一途径是删除下游单据。
这意味着 Push 一旦成功就进入了"只能向前"的区域——
这正是 `push_and_audit` 中途失败特别危险的原因（A-1）。

## 5. 规则（Rule）

按**求值时点**分类，决定了一条规则能不能真正拦住问题：

| 类型 | 求值时点 | 执行者 | 能否阻止中间态 |
|---|---|---|---|
| `precondition` 前置条件 | 动词执行前 | 客户端或服务端 | ✅ 能 |
| `invariant` 不变量 | 任意时刻 | 服务端 | ✅ 能 |
| `postcondition` 后置条件 | 动词执行后 | 客户端 | ❌ 只能发现 |
| `chain` 操作链约束 | 整条序列结束后 | CI（离线） | ❌ 只能事后追责 |

**当前 harness 的 4 条规则全部是 `chain` 类**——它们在 CI 里读历史日志，
运行期不参与任何决策。所以 A-1 的无补偿 Saga 在真实调用中完全不受约束，
即使 CI 事后判定"操作链不完整"，账套里的孤儿草稿已经存在了。

要真正治理原子性，需要补的是 `precondition`（发请求前拦截）
和一条新的 `chain` 规则——**补偿完备性**：
复合动词中途失败后，必须存在一条补偿记录，或有人显式接受这个中间态。
后者已由本次交付的 [`operation_audit.py:dangling_traces()`](../../tools/ontology/operation_audit.py) 实现。

## 五元之间的约束关系

```
              ┌──────────────┐
              │  规则 Rule   │  约束下面全部四者
              └──────┬───────┘
                     │
   ┌─────────┬───────┴────────┬──────────┐
   │         │                │          │
┌──▼───┐ ┌───▼────┐      ┌────▼────┐ ┌───▼────┐
│名词  │ │ 动词   │─作用→│  状态   │ │ 链接   │
│Noun  │◄┤ Verb   │      │  State  │ │ Link   │
└──┬───┘ └───┬────┘      └─────────┘ └───┬────┘
   │         │                            │
   │         └──── Push 类动词创建 ────────┘
   └──────────── 链接连接两个名词实例 ──────┘
```

四条应当成立、当前**全部缺失**的横向约束：

| 约束 | 含义 | 现状 |
|---|---|---|
| 名词 × 动词 | 只有适用的动词能作用于某名词（不该对基础资料 Audit） | ✗ 无校验（`MISS-01`） |
| 动词 × 状态 | 动词的前置状态必须满足（Push 要求源单已审核） | ✗ 仅服务端拦截，客户端不预校验 |
| 链接 × 状态 | 链接两端的状态变化必须保持不变量 | ✗ 无校验（`MISS-03`） |
| 动词 × 链接 | Push 前校验 `(from,to)` 是已登记的转换关系 | ✗ 无链接表（`MISS-02`） |
